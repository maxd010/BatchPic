# 自动处理功能速查卡

> 快速参考：BatchPic 自动处理功能的核心信息

## 🎯 一句话总结

**拖拽图片 → 自动处理 → 完成！**

## ⚡ 快速开始

```bash
# 1. 启动应用
npm run dev

# 2. 拖拽图片到窗口
# 3. 等待自动处理完成
# 4. 在 ~/BatchPic_Output/[时间戳] 查看结果
```

## 📊 默认参数

| 参数 | 值 | 说明 |
|------|-----|------|
| 质量 | 70% | 最佳平衡点 |
| 尺寸 | 原始 | 不改变 |
| 格式 | 原始 | 不转换 |
| 并发 | CPU 核心数 | 自动优化 |

## 🔄 进度状态

| 图标 | 状态 | 说明 |
|------|------|------|
| ⏱️ | Pending | 等待处理 |
| ⚙️ | Processing | 正在处理 |
| ✅ | Success | 处理成功 |
| ❌ | Failed | 处理失败 |

## 🎛️ 自动处理开关

### 何时关闭？

- ✅ 需要自定义参数
- ✅ 想先预览文件列表
- ✅ 只处理部分图片
- ✅ 测试不同设置

### 如何使用手动模式？

1. 关闭"自动处理"开关
2. 拖拽图片（只扫描）
3. 调整参数
4. 点击"开始导出图片"

## 📁 输出位置

```
~/BatchPic_Output/
└── YYYYMMDD_HHMMSS/
    ├── 图片1.jpg
    ├── 图片2.jpg
    └── 子文件夹/
        └── 图片3.jpg
```

## ⚠️ 常见错误

| 错误 | 原因 | 解决方案 |
|------|------|----------|
| Unsupported format | 格式不支持 | 转换为 JPG/PNG/WebP |
| Permission denied | 权限不足 | 检查文件权限 |
| Failed to read | 文件损坏 | 使用修复工具 |
| No space left | 磁盘空间不足 | 清理磁盘 |

## 🚀 性能参考

| 场景 | 性能 |
|------|------|
| 单张图片 | < 500ms |
| 100 张图片 | < 30s (4核) |
| 内存占用 | < 500MB |

## 💡 最佳实践

### ✅ 推荐

- 单次处理 < 500 张
- 关闭其他占用内存的应用
- 定期清理输出目录
- 保留原始文件作为备份

### ❌ 避免

- 处理超大批量（> 1000 张）
- 处理损坏的图片
- 在低内存设备上处理大量图片
- 删除原始文件

## 🔧 技术细节

### 支持格式

- ✅ JPG/JPEG
- ✅ PNG
- ✅ WebP
- ❌ GIF（计划中）
- ❌ AVIF（计划中）
- ❌ HEIC（计划中）

### 安全保障

- ✅ 路径验证（拒绝 `..` 和 `~`）
- ✅ 类型验证（只处理图片）
- ✅ 权限检查（确保可写）
- ✅ 参数验证（IPC 通信）
- ✅ 不覆盖原始文件

### 并发机制

```typescript
并发数 = CPU 核心数
处理方式 = 并发处理
失败策略 = 继续处理其他图片
```
