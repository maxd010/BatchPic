# 自动处理功能使用指南

## 概述

BatchPic 的自动处理功能让图片批量处理变得前所未有的简单。只需拖拽图片，系统会自动完成扫描、处理和导出，全程无需手动干预。

## 核心特性

### 🚀 拖拽即处理

传统工作流程：
```
拖拽图片 → 等待扫描 → 调整参数 → 点击处理按钮 → 等待完成
```

自动处理工作流程：
```
拖拽图片 → 自动完成！
```

### 📊 实时进度跟踪

每张图片都有独立的进度状态：

- **⏱️ 等待中** - 图片已识别，排队等待处理
- **⚙️ 处理中** - 正在压缩和优化
- **✅ 成功** - 处理完成，显示文件大小对比
- **❌ 失败** - 处理失败，显示错误原因

### 🎯 智能默认参数

自动处理使用经过优化的默认参数：

| 参数 | 默认值 | 说明 |
|------|--------|------|
| 质量 | 70% | 在文件大小和图片质量间取得最佳平衡 |
| 尺寸 | 保持原始 | 不改变图片尺寸 |
| 格式 | 保持原始 | 不转换格式 |
| 并发数 | CPU 核心数 | 充分利用多核性能 |

## 使用场景

### 场景 1：快速压缩单个文件夹

**需求**：将一个包含 50 张照片的文件夹快速压缩以便分享

**步骤**：
1. 打开 BatchPic
2. 将文件夹拖拽到应用窗口
3. 等待 10-15 秒
4. 在 `~/BatchPic_Output/[时间戳]` 找到压缩后的图片

**结果**：
- 原始大小：150 MB
- 压缩后：45 MB（节省 70%）
- 图片质量：肉眼无法区分

### 场景 2：批量处理多个来源的图片

**需求**：处理来自不同文件夹的图片

**步骤**：
1. 选择多个图片文件（可以来自不同位置）
2. 一次性拖拽到 BatchPic
3. 系统自动处理所有图片
4. 输出目录保持原始文件名

**优势**：
- 无需手动合并文件
- 保持原始文件名和顺序
- 一次操作完成所有处理

### 场景 3：处理大量图片

**需求**：处理 200+ 张图片

**步骤**：
1. 拖拽文件夹到 BatchPic
2. 观察进度面板实时更新
3. 如有失败，查看错误报告
4. 处理完成后收到通知

**性能**：
- 200 张图片（平均 2MB）
- 处理时间：约 60 秒（4 核 CPU）
- 内存占用：< 800 MB

## 自动处理开关

### 何时关闭自动处理？

在以下情况下，您可能希望关闭自动处理：

1. **需要调整参数** - 想要自定义质量、尺寸或格式
2. **预览文件** - 先查看扫描结果再决定是否处理
3. **选择性处理** - 只处理部分图片
4. **测试设置** - 验证处理参数是否符合预期

### 如何使用手动模式？

1. 关闭"自动处理"开关
2. 拖拽图片到应用（只会扫描，不会处理）
3. 查看扫描结果
4. 调整处理参数（如需要）
5. 点击"开始导出图片"按钮

## 错误处理

### 常见错误及解决方案

#### 1. 文件格式不支持

**错误信息**：`Unsupported image format`

**原因**：文件不是 JPG、PNG 或 WebP 格式

**解决方案**：
- 使用其他工具先转换格式
- 跳过该文件，继续处理其他图片

#### 2. 文件损坏

**错误信息**：`Failed to read image data`

**原因**：图片文件损坏或不完整

**解决方案**：
- 检查原始文件是否可以正常打开
- 尝试使用图片修复工具
- 从备份恢复文件

#### 3. 权限不足

**错误信息**：`Permission denied`

**原因**：无法读取源文件或写入输出目录

**解决方案**：
- 检查文件权限
- 确保输出目录可写
- 以管理员权限运行应用

#### 4. 磁盘空间不足

**错误信息**：`No space left on device`

**原因**：输出目录所在磁盘空间不足

**解决方案**：
- 清理磁盘空间
- 更改输出目录（未来版本支持）

## 输出目录结构

### 默认输出位置

```
~/BatchPic_Output/
├── 20240115_143022/          # 时间戳文件夹
│   ├── photo_001.jpg
│   ├── photo_002.jpg
│   └── subfolder/            # 保持原始目录结构
│       └── photo_003.jpg
├── 20240115_150830/          # 另一次处理
│   └── ...
```

### 文件命名规则

- **保持原始文件名**：不修改文件名
- **保持目录结构**：如果拖拽文件夹，保持内部结构
- **避免覆盖**：每次处理创建新的时间戳文件夹

### 时间戳格式

```
YYYYMMDD_HHMMSS
```

示例：
- `20240115_143022` = 2024年1月15日 14:30:22

## 性能优化建议

### 1. 批量处理大量图片

**建议**：
- 单次处理不超过 500 张
- 超大批量可以分多次处理
- 关闭其他占用内存的应用

**原因**：
- 避免内存溢出
- 保持系统响应性
- 更容易定位错误

### 2. 处理超大图片

**建议**：
- 超过 8000x8000 像素的图片会自动缩小
- 如需保持原始尺寸，先手动缩小到安全范围

**原因**：
- 超大图片可能导致内存不足
- 处理时间显著增加
- 输出文件可能过大

### 3. 并发处理优化

**系统自动优化**：
- 4 核 CPU：同时处理 4 张图片
- 8 核 CPU：同时处理 8 张图片

**用户无需干预**：
- 系统自动检测 CPU 核心数
- 自动调整并发数量
- 平衡速度和稳定性

## 常见问题

### Q: 自动处理会修改原始文件吗？

**A**: 不会。所有处理后的图片保存在新的输出目录，原始文件完全不受影响。

### Q: 可以自定义默认参数吗？

**A**: 当前版本使用固定的默认参数（质量 70%）。如需自定义，请关闭自动处理开关，手动调整参数后处理。

### Q: 处理失败的图片会怎样？

**A**: 失败的图片会在进度面板中标记，并显示错误原因。其他图片会继续处理，不受影响。

### Q: 可以取消正在进行的处理吗？

**A**: 当前版本不支持取消。建议在处理大批量图片前先测试少量图片。

### Q: 输出目录可以自定义吗？

**A**: 当前版本输出目录固定在 `~/BatchPic_Output/`。自定义输出目录功能计划在未来版本中添加。

### Q: 支持哪些图片格式？

**A**: 当前支持 JPG、PNG、WebP 三种格式。更多格式（如 AVIF、HEIC）计划在未来版本中添加。

### Q: 处理速度慢怎么办？

**A**: 
- 检查 CPU 使用率是否过高
- 关闭其他占用资源的应用
- 减少单次处理的图片数量
- 检查是否有超大图片（会自动缩小）

## 技术细节

### 处理流程

```mermaid
graph LR
    A[拖拽图片] --> B[扫描文件]
    B --> C[初始化进度]
    C --> D[创建输出目录]
    D --> E[并发处理]
    E --> F[更新进度]
    F --> G[显示通知]
    G --> H[完成]
```

### 并发处理机制

- 使用 `p-limit` 库控制并发
- 并发数 = CPU 核心数
- 每张图片独立处理
- 失败不影响其他图片

### 安全性保障

- **路径验证**：拒绝可疑路径（包含 `..` 或 `~`）
- **类型验证**：只处理支持的图片格式
- **权限检查**：确保输出目录可写
- **参数验证**：验证所有 IPC 通信参数
